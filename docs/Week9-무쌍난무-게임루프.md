## 2. 무쌍난무 설계

### 2.1 한 줄 요약
**적을 벨수록 게이지가 차고, 가득 차면 발동 — 일정 시간 동안 무적으로 광역 타격을 연타한다.**

### 2.2 데이터 흐름

```
[적 사망] → DeathEventQueue → DeathEventBridge(유일 소비자) → 킬 수
                                          │
                                          ▼
                                  MusouGaugeBridge (게이지 충전)
                                          │  가득 참 + 입력(R)
                                          ▼
                          발동: N회 반복 AttackRequest(광역) + 무적 + 셰이크
                                          │
                                          ▼
                              [ECS] AttackResolveSystem (기존 그대로)
```

### 2.3 결정 기록 (ADR)

**① 게이지는 GameObject(플레이어)가 소유한다**
- **이유**: 게이지는 입력·UI·연출과 붙어 있는 **플레이어 상태**다. ECS는 "누가 맞았나"만 알면 되고, 발동 결과는 이미 있는 `AttackRequest`로 충분하다. 아키텍처 원칙(플레이어=GO, 군중=ECS)에도 맞는다.
- 트레이드오프: ECS 시스템이 게이지를 못 읽는다 → 필요해지면 `PlayerState`에 필드를 추가(현재는 불필요).

**② 충전은 `DeathEventBridge`의 킬 수를 읽어서 한다 (큐를 직접 소비하지 않는다)**
- **이유**: `NativeQueue`는 **소비하면 사라진다.** `DeathEventBridge`가 이미 매 프레임 전부 드레인하므로, 게이지가 큐를 또 읽으면 킬카운트와 서로 이벤트를 뺏어 **둘 다 가끔 틀린다.** Week 8 히트스톱 트리거에서 내린 것과 **같은 원칙**: *큐 소비자는 1명, 나머지는 그 결과를 읽는다.*
- 구현: `DeathEventBridge.KillCount`(공개) → 게이지는 프레임당 증가분만큼 충전.

**③ 발동기는 "새 기술"이 아니라 광역기의 반복이다**
- **이유**: Week 3의 *"공격 = 데이터"* 설계 덕에 `AttackRequest`는 반경·데미지·넉백·경직을 파라미터로 받는다. 무쌍난무 = **큰 파라미터의 요청을 짧은 간격으로 여러 번** 쏘는 것 → 새 시스템 0개.
- 부수 효과: 밸런싱이 인스펙터 숫자 놀음이 된다(펄스 수·간격·반경·데미지).

**④ 발동 중 무적(i-frame)은 소비 지점에서 막는다**
- **이유**: 적의 공격은 `PlayerDamageQueue`에 쌓이고 `PlayerHealthBridge`가 소비한다. **큐는 계속 비우되 HP만 안 깎으면** 되므로, 소비 지점의 플래그 하나로 끝난다(큐가 안 비면 무적 해제 순간에 밀린 데미지가 한꺼번에 들어온다 — 반드시 비우면서 무시).
- 회피(Dodge)의 i-frame도 이 플래그를 그대로 쓴다 → §4에서 재사용.

### 2.4 파라미터 (초안 · 튜닝 대상)

| 항목 | 값 | 비고 |
|---|---:|---|
| 최대 게이지 | 100 | |
| 킬당 충전 | 1.5 | 병사 1300 기준 한 판에 여러 번 발동 가능 |
| 리더 킬 보너스 | +15 | 리더 처치 = 큰 보상(현재는 킬 수만 읽으므로 후속) |
| 발동 키 | **R** | 좌클릭 콤보·우클릭 광역기와 겹치지 않음 |
| 지속 | 2.4s | |
| 펄스 | 8회 (0.3s 간격) | |
| 펄스 반경 | 18 | 광역기(25)보다 좁고 자주 |
| 펄스 데미지 | 120 | 병사(100) 즉사, 엘리트(300) 3펄스 |
| 무적 | 지속 전체 | |

## 3. 게임 루프 (다음 단계 — 설계만)

- **목표**: 스테이지 클리어 = **리더 11기 전멸**(병사는 무한 스펙터클). 편성이 이미 리더 중심이라 목표가 자연스럽다.
- **패배**: 플레이어 HP 0 (이미 `PlayerState.IsDead` 존재).
- **UI**: 남은 리더 수 · 결과 화면(승/패) · 리트라이(씬 리로드).
- 열린 결정: 제한 시간을 둘지, 웨이브로 갈지.

## 4. 회피 (설계만)

- 입력(Space/Shift) → 짧은 대시 + **i-frame**(§2.3-④ 플래그 재사용) + 쿨다운.
- 대시는 `PlayerController` 이동에 임펄스로 얹는다(루트모션 아님).
